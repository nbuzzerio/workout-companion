# W-01 implementation checkpoint

Static frontend only. DEMO Monday is synthetic sample data, not imported history.
Sets are ordered arrays with separate weight/pounds, machine/position and hold/seconds
variants. `musclesSource` reserves optional raw spreadsheet metadata without choosing
a scale or parsing it. `sourceExamples` retains the requested readable notation.

API: `createPlan`, `createSession`, `updateSet`; `SessionStore.ensurePlan`, `list(date?)`,
`reopen(id)`, `save`, `complete`. Plan/session IDs are stable; new sessions use UUIDs.
Dates are local calendar strings, never UTC-derived dates. Prior completed performance
is shown separately from the current session. Session snapshots isolate plan changes.

IndexedDB database version 1 creates two stores. There are no clear/delete paths.
Unknown session record versions are rejected without rewriting data. Future migrations
must be additive or explicitly transform records without dropping history. Saves resolve
on transaction completion, not request success. A read/write transaction compares the
saved revision before updating; completed records, moved dates and stale revisions are
rejected. Explicit save/completion confirmation is in the UI; low-level API callers must
obtain confirmation themselves. Drafts are memory-only, labeled unsaved, and guarded on
page exit. Browser storage can still be cleared externally; this is not a backup system.
